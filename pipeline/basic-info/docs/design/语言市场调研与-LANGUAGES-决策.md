# 语言市场调研与 LANGUAGES 决策

> 已废弃（2026-07-19）：当前产品策略固定为 `en/es/de/fr/ja/ko`，运行时不再执行本文件描述的单游戏语言市场调研。本文件只保留历史设计背景。

## 目标

`site-identity.json` 的 `LANGUAGES` 不能再等同于“官方页面使用什么语言”。本项目的最终目标是通过多语言 SEO 文章获得广告收入，因此先用商业策略限定高价值候选市场，再调查这个具体游戏在候选语言中是否存在可验证需求。

## 编排

1. Roblox API 确认游戏身份。
2. 通用外部研究补齐官方链接、玩法和兑换码。
3. `language_market_research` 使用 ToAPIs Responses `web_search_preview` 独立联网；ToAPIs 失败时由现有客户端降级到 Perplexity。
4. 固定调查 `en/es/de/fr/ja/ko/it/nl`，并为每个候选返回 `include` 或 `exclude`，避免“没有返回”被误解为“调查后排除”。其他语言不消耗搜索预算。
5. 程序重新访问来源 URL，拒绝死链、私网地址和被禁止的竞对 Wiki。
6. 程序按确定性门槛生成 `facts.languages`，随后写入 `site-identity.json.LANGUAGES`。

原始模型结果和调用元数据保存在 `raw/language-market-research.json`；规范化候选、选择结果和说明保存在 `facts.json.languageMarket`。

## 入选门槛

- 英语和西班牙语是商业策略兜底，即使语言调研部分失败也保留 `en/es`。西班牙语同时服务西班牙及美国西语人群。
- 额外候选仅限德语、法语、日语、韩语、意大利语和荷兰语；英文覆盖美国、英国、加拿大、澳大利亚等英语高价值市场。
- 永不调查或输出中文。葡语、越南语、菲律宾语、俄语、土耳其语、印尼语、泰语、阿拉伯语、波兰语等不进入当前商业候选范围，即使存在一定自然讨论也不入选。
- 非英语候选置信度必须至少为 `0.70`。
- 必须有一个开发者提供的官方本地化来源，或者至少两个不同 URL 且来自至少两个独立发布者/域名的游戏特定证据。同一 URL 被模型拆成多个信号时仍只算一个来源。Roblox 自动生成的 `/pt/games/` 等本地化站点路由只翻译平台界面，不能单独证明游戏本身支持该语言或存在市场热度。
- 单篇页面、通用 Roblox/动漫热度、无落地页的搜索摘要、重复转载和明显机器翻译 SEO 页面不足以入选。
- 最多选择 4 种语言，英语和西班牙语固定排前两位，其他语言按置信度排序。
- Fandom、wiki.gg、fextralife 不作为语言需求证据。

## 与首页生成的关系

首页 LLM 不再自行决定语言。其内部 `languages` 会被程序用独立调研结果确定性覆盖，避免同一流程出现两套互相矛盾的语言建议。

## 与文章阶段的边界

本项目仍不生成 SEO 文章。下游文章工具应把 `site-identity.json.LANGUAGES` 当作唯一语言范围，并在最终模板的 `intake/articles/<locale>/` 中交付一一对应的目录。模板的 `check:intake` 负责最后的范围交叉检查。
