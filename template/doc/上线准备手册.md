# 上线准备手册（人类操作，阶段 a）

这份手册只管一件事：**准备工作**——把东西按约定路径放进 `intake/`。跟 AI 对话、执行代码改动不在这里，那部分在 [doc/新游戏上站提示词流程.md](新游戏上站提示词流程.md)（阶段 b）。

按下面的步骤顺序做，不用理解模板内部是怎么实现的。

## 你会用到的目录结构

`intake/articles/` 不会随模板自带——它是你直接把 seoscout 整个产出文件夹复制/改名进来的（预先建一个空的反而容易造成"文件夹里又套了一层同名文件夹"的复制事故）。

下面这几个都是**固定约定路径**，按这个位置放好就够了，不需要另外填配置文件说明"东西放在哪"：

```
<项目根目录>/
└── intake/
    ├── articles/                ← 第 1 步：你把 seoscout 产出的整个文件夹改名/复制成这个
    ├── site-identity.json       ← 第 2 步：身份字段（GAME_NAME/OFFICIAL_GAME_URL 等）
    ├── site-content.json        ← 第 3 步：首页文案（结构化成品格式）
    ├── hero/（或 hero.jpg/.png/.webp）  ← 第 4 步（可选）
    └── favicon/（或 logo.png）          ← 第 4 步（可选）
```

`new-site.env` 不在上面这张图里——它现在是**完全可选**的覆盖文件，只有素材放在了非约定路径才需要，见第 5 步。

---

## 第 0 步：从纯净模板 clone 一份新目录

> 当前标准入口已经改为 `game-wiki-factory`。不要单独 clone 本模板；在工厂根执行 `python gamewiki.py "游戏名"`，编排器会把模板同步到 `Games/<slug>/` 并保留 intake/checkpoint。下面的手工步骤仅用于理解或紧急排障。

不要直接在工厂 `template/` 中写具体游戏内容——它必须保持空壳状态。

```bash
python C:/Users/liang/Documents/Games/game-wiki-factory/gamewiki.py "游戏名"
cd C:/Users/liang/Documents/Games/<游戏slug>-wiki
```

## 第 1 步：文章

把 seoscout 产出的整个文章文件夹复制进项目根目录，改名成 `intake/articles`（不管它原来叫什么、内部是什么目录结构、嵌套几层，整个文件夹一起搬过来，不要只搬里面的内容）。

- 格式要求：每个文件必须以 `export const metadata = {...}` 开头，里面要有 `category` 字段——**这个字段的值就是这篇文章最终归属的分类**（也就是导航栏最终会出现的分类项），不需要你另外说明"要哪些分类"。
- 不需要你自己按语言/分类整理文件夹，AI 会在阶段 b 的 Part 3 读每篇文章的 `category` 字段自己归位。

## 第 2 步：身份字段

存成 `intake/site-identity.json`——格式（哪些必填、大小写要求）见 [doc/homepage-info-schema.md](homepage-info-schema.md)。可以自己写，也可以让负责第 3 步的 agent 一起产出。这份文件是 `GAME_NAME`/`OFFICIAL_GAME_URL`/`DISCORD_URL`/`YOUTUBE_CHANNEL_URL`/`FANDOM_URL`/`YOUTUBE_VIDEO_ID`/`LANGUAGES` 的标准来源，**不需要再额外填任何配置文件**。

多语言站点要在这里用 `LANGUAGES` 声明本次实际要交付哪些语言（如 `["en", "es"]`）——这是可选字段，但填了之后 `check:intake` 会拿它跟第 1 步 `intake/articles/<locale>/` 下实际存在的语言目录逐一核对，缺了哪个语言、或者多了哪个没声明的语言都会直接报出来，不用等上线后才发现某个语言没交齐。只做单语言（英文）不需要填这个字段。

## 第 3 步：首页信息文档

**推荐：直接给成品格式，跳过阶段 b 的 AI 对话、一条命令 `npm run launch:site` 跑完。** 按 [doc/homepage-info-schema.md](homepage-info-schema.md) 定义的结构化格式，存成 `intake/site-content.json`（跟第 2 步的 `site-identity.json` 平级，不需要单独建子目录）。这种格式下文案必须已经是成品——脚本只做字段搬运，不会替你把研究笔记改写成营销文案。主题色不需要你操心——固定用模板统一的配色，不是每个站点单独填的字段。已经用 mock 数据 + 多个真实游戏验证过全流程零人工干预跑通。

**备选：手上只有自由格式调研笔记，需要 AI 先读懂再改写。** 不需要为这些原始笔记专门建目录、存进 `intake/`——脚本从来不会读取笔记原文本身，只有你/AI 最终产出的 `intake/site-content.json` 才会被读取，所以原始笔记放哪都行：直接在阶段 b 的对话里把内容贴给 AI，或者告诉 AI 笔记文件实际所在的路径（不必在这个项目目录里），让它读完直接产出 `intake/site-content.json`。原始笔记不管是分几份文档产出的，都不需要先手动合并成一个文件，全部给 AI 读就行。

**再退一步：连自由格式笔记都没有，只能直接问人。** 这种情况下把 [SITE-CONFIG-TEMPLATE.md](../SITE-CONFIG-TEMPLATE.md) 当问题清单，一项项问，答案照样整理成 `intake/site-content.json`。

> 旧项目遗留提示：`intake/homepage-info/site-content.json`（嵌套一层子目录）这条路径仍然被脚本识别，纯粹是为了不破坏已经用这种结构上线的老项目——新项目不要再新建这个子目录，统一用上面第 3 步推荐的扁平路径 `intake/site-content.json`。

格式不限（Markdown、里面嵌 JSON 都行），但内容合起来至少要覆盖这几项，AI 会自己读取翻译，不需要你按模板字段名重新整理：

- 游戏名称、一句话简介
- Hero 区文案：大标题怎么写、一两句话介绍、想展示哪几个数字（访问量/在线人数/更新时间等）
- 游戏介绍：开发商、平台、类型这些事实信息
- （可选）时效性内容：有没有兑换码/排行榜这类需要首页单独一块展示的东西，没有就写"无"
- （可选）分类精选内容：如果游戏有角色/职业/道具/异常这类"条目式"内容（区别于攻略型文章），且数量足够（每类 4 条以上），想让具体条目名直接出现在首页，就分类别列出来（每类给条目名 + 一行描述 + 对应文章链接），对应 `home.extraSections`，格式见 [doc/homepage-info-schema.md](homepage-info-schema.md)；没有就跳过，首页不会因此空白
- FAQ 问答，建议 4-6 条

**不需要你挑选首页"精选攻略"具体是哪几篇文章**——这个模块在阶段 b 的 Part 3（文章接入之后）由 `npm run generate:featured` 按固定规则自动生成，不是编辑判断，不需要你输入候选清单，也没有"忘了填"这回事。规则细节见 [doc/新游戏上站提示词流程.md](新游戏上站提示词流程.md) Part 3。如果你确实有明确想指定的文章，不用写在这份文档里——上线时在项目根目录建一个 `intake/featured-override.json`，格式是 `[{"category": "guide", "slug": "文章文件名（不含 .mdx）"}, ...]`，脚本检测到这个文件就直接按它来，不跑自动算法。

## 第 4 步：素材（可选，没有就跳过，不影响上线）

- Hero 图源文件 → 放 `intake/hero/`（可以放多张候选图，脚本按文件名排序自动选第一个）或 `intake/hero.*`（单文件，webp/jpg/png 都行，不用自己转格式，后缀也不用纠结）
- Logo/favicon，两种情况选一种：
  - **只有一张 logo 源图**：放 `intake/logo.*`，模板会据此生成整套 favicon。
  - **已经用生成器（如 realfavicongenerator.net）生成好一整套**（`favicon.ico`/`favicon-16x16.png`/`favicon-32x32.png`/`apple-touch-icon.png`/`android-chrome-192x192.png`/`android-chrome-512x512.png`/`site.webmanifest`）：把整个文件夹放进 `intake/favicon/`——这种情况更省事，直接复制现成文件，不需要重新生成。

（YouTube 预告片视频 ID 不是文件，放进第 2 步的 `intake/site-identity.json` 的 `YOUTUBE_VIDEO_ID` 字段，可以直接贴完整视频链接，不用自己截取 ID。）

## 第 5 步（可选，只有想覆盖某条约定路径时才需要）：`new-site.env`

按上面第 1-4 步的固定路径放好之后，**不需要创建任何配置文件**，直接跳到下面的校验步骤。只有素材放在了非约定路径、需要手动指定时才需要：

```bash
cp new-site.example.env new-site.env
```

打开 `new-site.env`，只填要覆盖的那一行（比如 `HERO_IMAGE_SOURCE` 指向一个非约定路径），其余留空——留空的字段照样按第 1-4 步的约定路径自动解析。域名不在这里填——本地开发和 `launch:site` 全程不需要域名，真正生效的是部署到 Vercel 等平台时配置的 `NEXT_PUBLIC_SITE_URL` 环境变量 + 绑定的真实域名。Vercel 推荐填写完整的 `https://game.example.com`；误填裸域名会自动补 HTTPS。该值会公开出现在 canonical、Open Graph、JSON-LD、sitemap 和 robots 中，因此无需开启 Sensitive（团队策略强制时可以保留）。修改变量后必须重新部署，并运行 `npm run verify:deploy`；验收会检查线上 HTML metadata，而不只看 HTTP 200。

## 校验

不管有没有创建 `new-site.env`，都跑一下校验脚本，把路径写错、格式不对这类结构性问题在这一步解决掉，不要留到开 AI 对话之后才发现：

```bash
npm install   # 第一次 clone 出来还没装依赖的话，先跑这个
npm run check:intake
```

`YOUTUBE_VIDEO_ID` 贴的完整链接会被自动识别成纯 ID；`HERO_IMAGE_SOURCE`/`FAVICON_SET_DIR`/`LOGO_SOURCE` 没有显式配置或指向的文件不存在时，会自动按第 4 步的约定路径解析并打印用了哪个文件；素材完全找不到这类没法替你决定的问题，会以 `warning`/`error` 的形式列出来，照着提示处理。有 `error` 就必须先解决，`warning` 视情况决定要不要处理。

## 完成检查表

跑完这几条，就可以进入阶段 b 了：

- [ ] `intake/articles/` 里有 `.mdx` 文件，抽查几篇确认是 `export const metadata` 开头
- [ ] `intake/site-identity.json` 已经提供，`GAME_NAME`/`OFFICIAL_GAME_URL` 两个必填项填完了（或者用 `new-site.env` 覆盖也行）
- [ ] `intake/site-content.json` 已经提供，内容合起来覆盖了"第 3 步"列的几项（老项目用的是嵌套的 `intake/homepage-info/site-content.json` 也算数，新项目不要新建这个子目录）
- [ ] `npm run check:intake` 跑过，没有残留 `error`（`warning` 已经看过、确认可以接受）

## 下一步

准备工作到此结束。开一个新对话，把 [doc/新游戏上站提示词流程.md](新游戏上站提示词流程.md) 的 **Part 0** 提示词原文复制粘贴发给 AI，然后依次发 Part 1 → 2 → 3 → 4 → 5，每个验证通过再发下一个。

## 一个容易搞混的概念：导航分类 ≠ 首页模块

- **Header 导航栏 + 侧边栏的分类项**：完全由第 1 步文章里的 `category` 字段自动决定。你的文章里出现了 `guide`/`bosses`/`codes` 这些 `category` 值，阶段 b 的 Part 3 跑完 `npm run sync:categories` 之后，导航栏就会自动长出这些分类——**这是自动的，你不需要在任何地方单独声明"要有哪些导航项"**。
- **首页展示哪些模块（精选攻略区 / 时效工具区 / 分类精选区）**：精选攻略区（`home.featured`）由 AI 在 Part 3 按**固定规则**自动从已收录文章里挑，不需要你在第 3 步指定候选清单（也不等于"每个分类挑一篇"或"最新的几篇"——最新的几篇是 Latest Updates 区块自动做的事，跟精选区是两回事）。时效工具区（`home.liveTools`，兑换码/排行榜这类）和分类精选区（`home.extraSections`，角色/职业/道具这类"条目式"内容按分类分块展示）都不是从文章列表能自动推出来的内容，还是要看第 3 步文档里有没有提供，没有就整块跳过。

简单说：**分类是文章结构自动推出来的，精选攻略也是从文章结构按规则自动推出来的，时效工具区和分类精选区都是人工提供的**——新增一个分类不会自动出现在首页精选区或分类精选区，但会在下次 Part 3 重新跑规则时被精选攻略的规则纳入考虑范围；分类精选区没有自动规则，想让新分类出现在首页就要手动往 `home.extraSections` 加一块。

`home.liveTools` 和 `home.extraSections` 的区别：`liveTools` 是单个固定区块，专门给"兑换码/梯度榜/服务器状态"这类**时效性**内容用；`extraSections` 是一个数组，可以有 0 个到多个区块，专门给"角色/职业/道具/异常"这类**条目式、不随时间过期**的内容用，两者是并列关系，不是互相替代——一个游戏可以同时有 `liveTools`（一块）和 `extraSections`（好几块），也可以都没有。
