## 契约变化

模板当前要求两份基础文件，并为每个非英语语言增加一份本地化内容文件：

|文件|当前允许结构|程序行为|
|---|---|---|
|`intake/site-identity.json`|7 个全大写 key；`GAME_NAME`、`OFFICIAL_GAME_URL` 必填，`LANGUAGES` 为小写 ISO 639-1 数组|确定性生成；链接、YouTube ID 和语言代码强校验；语言范围来自独立联网市场调研|
|`intake/site-content.json`|顶层仅 `site/home`，内部 key 严格 camelCase；`extraSections` 仅在真实文章已接入时可选|确定性转换，所有对象拒绝未知 key|
|`intake/site-content.<locale>.json`|LANGUAGES 每个非英语代码一份；与英文版完全同构|LLM 只写母语化字符串；程序强校验 key 树、数组长度/顺序、数字事实、游戏名及 `href/*Href/category` 不变|
|`intake/hero.<ext>`|一张可解码的横向 Hero|从已验证候选中确定性选择第一张|
|`intake/favicon/`|ICO、5 个固定尺寸 PNG、`site.webmanifest` 共 7 个文件|逐文件校验并复制，不带内部 `source-icon.png`|

`themeColor`、`modules`、`displayType`、`sidebarCodes`、`tertiaryCta`、`home.start`、`home.explore.modules` 均为旧字段，正式输出中不再出现。

`home.hero.title/secondaryCtaHref/videoId` 以及 `home.featured/categories/updates` 属于模板自动字段，内容文件不得覆盖。

## 实现

`src/gamewiki_automation/template_contract.py` 负责：

1. 从 `facts.json` 确定性生成 `site-identity.json`；
2. 从 facts 与内部首页文案确定性生成新版 `site-content.json`；
3. 为 LANGUAGES 中每个非英语代码生成 `site-content.<locale>.json`；
4. 使用严格 Schema 校验精确 key、大小写、类型和数组结构，并递归对照英文版结构；
5. 执行事实一致性、禁止字段、占位符、FAQ 1–3 句、数字序列、游戏名、不可翻译路径和防整份英文照抄检查；
6. JSON、本地化文件或素材任一失败时，删除整个 `template-intake/`，只保留内部审计文件与失败报告。

正式输出：

```text
output/<slug>/site-identity.json
output/<slug>/site-content.json
output/<slug>/template-validation-report.json
output/<slug>/template-intake/site-identity.json
output/<slug>/template-intake/site-content.json
output/<slug>/template-intake/site-content.<locale>.json（每个非英语语言一份）
output/<slug>/template-intake/hero.<ext>
output/<slug>/template-intake/favicon/（7 个文件）
```

## 样本结果

|游戏|语言|模板契约|本地化文件|
|---|---|---|---|
|Anime Paradox X|en/es|pass|`site-content.es.json`|
|Anime Expeditions|en/es/ja|pass|`site-content.es.json`、`site-content.ja.json`|
|PursuitCore|en/es|pass|`site-content.es.json`|

PursuitCore 的研究结果曾把 Reddit 视频页记录为 trailer；双文件校验拒绝把它写入只接受 YouTube 的 `YOUTUBE_VIDEO_ID`，最终安全输出空字符串。
