### 1\.3 首页模块数据采集（分门别类列，提升游戏词密度）



**目标 **：一次性获取首页 8 个内容模块的完整数据——包括模块规划（名称、描述、展示形式）和具体数据条目（highlights）。

**数据来源 **：ChatGPT 联网搜索

**提示词 **：

```Plaintext
主题词：{TOPIC}
我要做首页，准备8个小模块（除hero、除FAQ），覆盖用户常见SEO谷歌搜索（如codes、beginner guide、tier list），且资料网上可以搜索到，按重要程度排序。禁止无意义模块。

请严格按以下 JSON 结构输出，每个模块一个对象，匹配 en.json 的 home.explore.modules 格式：

{
  "modules": [
    {
      "order": 1,
      "name": "<全英文，格式：游戏名 xxx，如 Star Savior Codes>",
      "description": "<2-3 句模块介绍>",
      "href": "</模块对应内页路径，如 /codes>",
      "displayType": "<仅限 4 种：code-cards | step-by-step | tier-grid | card-list>",
      "highlights": [
        {"label": "<标签/序号/等级>", "detail": "<具体内容描述>", "badge": "<可选，如 Active/New>"}
      ],
      "references": ["<具体可访问的网站链接，禁止捏造>"]
    }
  ]
}

要求：
- modules 数组包含 8 个对象，按重要程度排序
- href 为该模块点击后的跳转路径（内部页面 slug）
- displayType 仅限 4 种：code-cards（兑换码卡片）、step-by-step（步骤指引）、tier-grid（等级网格/S/A/B/C）、card-list（普通卡片列表）
- highlights 中填充真实游戏数据，禁止捏造；结构由 displayType 决定：
  - code-cards：每条为 1 个兑换码（label=码名，detail=奖励，badge=状态如 Active/Expired）
  - step-by-step：每条为 1 个步骤（label=序号，detail=步骤内容）
  - tier-grid：每条为 1 个等级（label=S/A/B/C，detail=该等级包含的内容）
  - card-list：每条为 1 个卡片（label=图标文字，detail=卡片内容）
- references 必须有值，列出真实可访问的链接
- references 严禁包含竞对站、Wiki/Fandom/聚合 wiki 链接（如 wiki.gg、fandom、fextralife、第三方攻略 wiki）；优先使用官网、官方商店、官方社媒、官方公告、官方视频、权威媒体
- 只输出 JSON，不要包含任何 markdown 标记或解释文字
```



**产出数据清单 **：

|数据项|说明|
|---|---|
|模块顺序|order 1\-8，按 SEO 价值排序|
|模块名称|格式「主题名 \+ 功能词」，如 "Cursed Gear Codes"|
|模块描述|2\-3 句介绍|
|跳转路径|href，内页 slug|
|展示形式|displayType，仅 code\-cards / step\-by\-step / tier\-grid / card\-list|
|数据条目|highlights 数组，每条含 label \+ detail \+ 可选 badge|
|参考链接|真实可访问的外部链接|

### 2\.2 关键词分类



**目标 **：将 4 个数据源关键词汇总，按搜索意图分类，

**最终产出最多 40 \- 60 个关键词（内页）、最多 8 个分类（一级导航栏） ****。**

新站刚上线，一般不建议放 太多内页，100以内。



**数据来源 **：ChatGPT 分析（接收所有数据源关键词）

**输入 **：上述 4 个 JSON 文件中的关键词数据

**提示词 **：

```Plaintext
{所有数据源的关键词文本}

以上是关键词，给出json。
游戏名：{KEYWORD}

对【所有关键词】分类，确保覆盖所有关键词，必须有的分类：guide。
分类禁止大空，例如gameplay、general。
**分类名必须是单个英文单词**（如 guide、codes、classes、weapons），禁止用连字符拼接（如 community-resources ❌）。固定词组如 tier list 用空格分隔，不用连字符。
**严格限制最多8个分类，最多40个关键词**，如果关键词较多，合理合并相近分类，优先保留高流量关键词。
假设有Codes分类: 其分类下只能有一个关键词。

关键词中 核心主词 和 非本主题词 过滤掉，禁止生成 Wiki 分类。
如果关键词属于作弊、外挂、脚本、注入、漏洞利用、自动刷取等风险意图（如 script、hack、exploit、pastebin、auto farm、auto quest、auto eggs、no key、inf money），必须直接过滤，禁止单独成类，也禁止保留在任何分类中。

同义词要合并（合并后的关键词必须是搜索量最大、大众习惯搜索那个）。
并给出同义词合并后，还有多少，即还能做多少"一个词一个内页"的精品内容。
分类1：xxx
关键词1
关键词2
…
注意事项：游戏 reddit 等这类，也属于这个主题不能过滤。

关键词优化：
1、**所有关键词必须是纯英文 ASCII**，禁止出现任何中文字符、中文括号（）、日文假名、韩文等非英文字符；若原词含中文，翻译成英文；若需要说明主题类型，只允许写成英文（如 roblox game），且仅在必要时作为关键词内部的普通单词出现，绝对不允许用括号包裹
2、可修改某单词拼写错误，但禁止扩写
3、主题词统一，**关键词命名统一成 {游戏词} xxx**（即每个关键词都以 "{KEYWORD}" 开头，后接小写英文长尾；禁止在 {KEYWORD} 后或关键词任意位置拼接主题类型、括号、中文、连字符补充说明）。
除此之外，禁止做其他修改。

注意事项：
**Mutually Exclusive（相互独立）**：
1、不同分类下，不要存在包含关系，例如Guides和Beginner Guides
2、一个分类下,不能出现同义关键词（例如只是单复数区别）

Collectively Exhaustive（完全穷尽）
一个分类下所有有效关键词要覆盖这个分类可能的所有需求，且具备一定逻辑关系（顺序或包含）
还有一些是YouTube视频标题，也请分析高流量视频，提取关键词。
手动写,禁止使用脚本处理。
每个分类下,重要(流量大的)关键词排在前面。

输出格式必须是json：
{
  "topic_name": "{KEYWORD}",
  "categories": [
    {
      "category": "分类名",
      "keywords": ["keyword1", "keyword2"]
    }
  ]
}
```



**产出数据清单 **：

|数据项|说明|
|---|---|
|分类|最多 8 个，每个一个英文单词（guide、codes、classes 等）|
|关键词|最多 40 个，最少 30 个，统一格式「游戏词 \+ 长尾词」|
|分类互斥|不同分类间无包含关系|
|同义合并|同义词只保留搜索量最大的那个|

### 2\.3 seoscout：开源SEO文章生成工具



如果你想快速生成文章，可以用我开发的开源工具 **seoscout **一行命令搞定从搜索到生成的全流程。

支持 多并行、缓存机制、重试机制。



#### 什么是 seoscout



seoscout 是一个命令行工具，输入关键词文件，自动完成：



1. **search **— 在 YouTube（yt\-dlp）和 Google（Serper API）并行搜索

1. **collect **— 提取 YouTube 视频字幕 \+ 网页正文（Jina Reader）

1. **generate **— 用 LLM 生成 SEO 优化的英文 Markdown 文章

1. **translate **— 翻译成多语言（支持任意语言）

按执行步骤顺序，各阶段依赖的外部服务如下：



##### 步骤 1：搜索（search）



|服务|变量|技术原理|获取方式|费用|
|---|---|---|---|---|
|YouTube 搜索<br>|无需 API Key|`yt-dlp` 解析 YouTube 搜索结果页面，提取视频标题、播放量、时长|无需注册|免费|
|Google 搜索<br>|`SERPER_API_KEY`|调用 Serper API 解析 Google 搜索结果，返回标题、URL、摘要|[serper\.dev ](https://serper.dev/)注册|免费额度 2500 次，超出 $2/1000 次|

|服务|变量|技术原理|获取方式|费用|

#### 使用流程



**准备关键词文件 ** `keywords.json` ：



分类格式（推荐，文章按分类子目录输出）：

```JSON
{
  "topic_name": "My Game",
  "languages": ["es", "pt", "de", "fr"],
  "categories": [
    {
      "category": "Guide",
      "keywords": ["My Game beginner guide", "My Game walkthrough"]
    },
    {
      "category": "Tier List",
      "keywords": ["My Game best characters tier list"]
    }
  ]
}
```



- `topic_name` （必填）：主题名，用于项目命名和 YouTube 搜索过滤

- `languages` （可选）：目标翻译语言，填了 `seoscout run` 会自动执行翻译，不填则只生成英文文章

- `categories` （必填）：关键词分类，每篇文章输出到对应子目录

- 

扁平格式（所有文章输出到同一目录）：

```JSON
{
  "topic_name": "My Game",
  "keywords": ["My Game beginner guide", "My Game tips and tricks"]
}
```



**运行命令 **：



```Bash
# 方式一：分步执行（可在每步之间人工审核/筛选）
seoscout search --keywords keywords.json      # 步骤 1：搜索
seoscout collect --keywords keywords.json     # 步骤 2：采集
seoscout generate --keywords keywords.json    # 步骤 3：生成文章
seoscout translate --keywords keywords.json --lang es,pt,de,fr # 步骤 4：翻译成多语言（可选）

# 方式二：一行跑完 search + collect + generate + translate（JSON 里填了 languages 才翻译）
seoscout run --keywords keywords.json
```

### 2\.4 文章生成



**目标 **：基于搜集到的参考资料，为每个关键词生成一篇 SEO 优化英文文章。



**数据来源 **：LLM 生成（参考资料来自 2\.3 的搜集结果）



**输入 **：关键词 \+ 搜集到的 merged 数据（YouTube \+ Web 内容）



**输出目录 **：

- 分类格式： `articles/en/{category}/{keyword}.mdx` （如 `articles/en/guide/my-game-beginner-guide.mdx` ）

- 扁平格式： `articles/en/{keyword}.mdx`

- 

> 💡 seoscout： `seoscout generate --keywords keywords.json` （生成后自动验证，不合格的自动修复重试）

#### 文章生成提示词



**提示词 **（来源： `seoscout/templates/generate.md` ）

```Plaintext
依赖变量（由脚本自动注入）：
- {merged_data}    : 搜集到的参考资料（JSON 格式，包含 YouTube 和 Web 内容）
- {current_date}   : 当前日期（格式：YYYY-MM-DD）
- {category}       : 内容分类 slug（如 bosses、races、guide）

你是一位拥有丰富经验、专门撰写游戏博客 SEO 内容的资深文案作者。

## 参考资料

{merged_data}

## 文章标题规则

根据参考资料中的关键词（keyword 字段）和内容自动生成文章标题：
- 必须在 50-60 字符之间
- 必须包含主关键词
- 必须吸引人点击
- 必须清楚传达文章目的

## 文章描述规则

用 1-2 句自然的话描述页面内容，包含 核心关键词
长度控制在 150-160 个字符
避免关键词堆砌（谷歌现在更依赖语义分析，而非关键词密度）
可以使用引人注目的号召语（如"Get the latest..."、"Discover..."）

## 撰写要求

1. 撰写一篇全原创的博客文章，约 1600 词
2. 在文中至少插入 9 次主关键词：
   - 在 title 字段中出现一次（会被页面模板自动渲染为 H1）
   - 在前 120 词内出现两次
   - 在正文中自然融入 4 次以上
3. 自然地融入语义相关词和 LSI 关键词
4. 提供实用的技巧、统计数据或示例
5. 引用参考资料时请意译，避免直接复制
6. 标注社区来源信息（"玩家经验"或"社区报告"）
7. 添加 1 个权威外部链接（官网、Steam、知名游戏媒体）
8. 使用描述性锚文本

## 文章结构

- 以 JS metadata export 开头（见下方输出格式）
- **不要生成 H1 标题**（title 作为 H1，直接从 H2 正文开始）
- 4-6 个 H2 标题，可选 H3 子标题
- **多用 Markdown 表格**展示对比、数据、步骤、排名等信息（至少 3-5 个表格）
- 使用项目符号列表
- 每段控制在 120 词以内
- 以 FAQ 区收尾（3-4 组问答，使用主关键词至少一次）

## 引言部分

- 3 句话内设下钩子，吸引读者
- 立即回答"为什么这很重要"

## 输出格式

输出以 JavaScript metadata export 开头的 Markdown 文件：

export const metadata = {
  title: "文章标题（50-60 字符，包含主关键词）",
  description: "SEO 描述（最多 155 字符），包括用户感兴趣的关键词",
  category: "{category}",
  date: "{current_date}",
}

[文章正文从这里开始，标准 Markdown 格式，不含 H1]

## 重要提醒

- 不要用代码块（```）包裹文章内容
- 文章必须以 export const metadata = { 开头
- 使用自然流畅的美式英语
- 遵循 Google「Helpful Content」指南
- 以用户价值为核心，避免关键词堆砌
- 确保信息准确

现在请按照以上所有要求生成完整的英文文章。
```

**提示词 **（来源： `seoscout/templates/translate.md` ）

```Bash
依赖变量（由脚本自动注入）：
- $language_name   : 目标语言名称（如 Spanish、Japanese）
- $lang_code       : 目标语言代码（如 es、ja）
- $content         : 待翻译的英文 MDX 文章内容

将以下 MDX 内容从英文翻译为 $language_name。

重要规则：
1. 将所有文本内容自然、流畅地翻译为 $language_name
2. 保持所有 Markdown 格式不变（标题 ##、列表 -、加粗 **、链接 []、表格等）
3. 保持所有 HTML 标签不变
4. 保持所有 URL 不变
5. 保持文章结构和长度一致

元数据翻译规则：
- title：必须翻译为 $language_name
- description：必须翻译为 $language_name
- summary：必须翻译为 $language_name（如存在）
- 其他所有元数据字段保持不变（category、date、lastModified、image 等）
- 元数据块必须保持 JavaScript export 格式，不得使用 YAML frontmatter（---）

目标语言：$language_name ($lang_code)

英文原文：

$content

关键输出规则：
1. 仅输出翻译后的 MDX 内容，不要添加任何其他文字
2. 直接以 `export const metadata = {` 开头 — 禁止使用 YAML frontmatter（---）
3. 不要将输出包裹在代码块中
4. 不要添加任何解释或说明
5. 输出必须是有效的 .mdx 文件，包含 JS export 元数据 + Markdown 正文
```
