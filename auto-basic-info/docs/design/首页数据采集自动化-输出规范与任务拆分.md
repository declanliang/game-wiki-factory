# Roblox 首页数据采集自动化：输出规范与任务拆分

> 设计状态：V1 草案  
> 日期：2026-07-16  
> 范围：只处理 [`docs/source/第四课、游戏首页、文章页建站数据准备 副本.md`](../source/第四课、游戏首页、文章页建站数据准备%20副本.md) 的“## 一、首页数据采集”  
> 当前阶段：设计，不编写实现代码

## 1. 产品目标

用户只提供一个 Roblox 游戏词：

```text
Anime Expeditions
```

系统自动输出：

1. 首页基础信息；
2. 官方链接和可用媒体；
3. 首页英文文案和 SEO 配置；
4. 主题色和默认明暗模式；
5. 多语言优先级；
6. favicon 生成提示词及后续图标包；
7. 首页内容模块；
8. 字段级来源和验证报告。

用户不需要提供 Roblox URL、Place ID、Universe ID、开发组或社群链接。

## 2. 设计原则

### 2.1 保留用户现有工作方式

核心内容仍由联网 GPT 研究和生成。第一版不是建设复杂搜索引擎，而是把网页版操作迁移为可重试、可验证的 API 工作流。

### 2.2 官方事实优先

Roblox 能直接返回的字段，不让模型通过第三方网页猜测：

- 游戏名；
- 描述；
- 开发者；
- Place ID / Universe ID；
- 在线人数、访问量、收藏量；
- 创建和更新时间；
- 类型、服务器人数；
- 图标和缩略图。

### 2.3 事实与文案分离

所有字段分为三类：

|类型|含义|例子|
|---|---|---|
|Fact|可以由来源直接证明|开发组、访问量、Discord URL|
|Inference|根据证据作出的判断|语言优先级、默认深色主题|
|Copy|不声称是外部事实的站点文案|Hero 描述、CTA、Footer 介绍|

生成模型可以自由撰写 Copy，但不能用 Copy 补齐缺失的 Fact。

### 2.4 输出结构与证据分离

网站前台只消费简洁配置；内部另存证据、置信度和错误信息。这样不必把引用字段塞入每段首页文案。

### 2.5 资料不足时允许缺失

- 不强制编造八个模块；
- 不强制凑出四门语言；
- 不强制生成有效兑换码；
- 不存在独立官网时使用 Roblox 官方游戏页；
- 没有可靠 Hero 图时输出缺失状态，不生成假下载链接。

## 3. 第一版输入

### 3.1 用户输入

```json
{
  "gameName": "Anime Expeditions",
  "platform": "roblox"
}
```

其中 `platform` 第一版固定为 `roblox`，界面上可以不展示。

### 3.2 内部运行参数

内部参数不要求用户填写：

```json
{
  "locale": "en",
  "maxLanguages": 4,
  "maxModules": 8,
  "allowCommunitySources": true,
  "generatedAt": "2026-07-16T00:00:00Z"
}
```

## 4. 第一版输出目录

建议每个游戏单独输出：

```text
output/anime-expeditions/
├── 00基础信息.md
├── 00首页信息.json
├── 00首页模块.json
├── facts.json
├── evidence.json
├── validation-report.json
├── raw/
│   ├── identity.json
│   ├── roblox.json
│   ├── web-research.json
│   └── module-research.json
└── assets/
    ├── media.json
    └── favicon/
```

说明：

- `00基础信息.md`：面向人的完整报告，类似当前 ChatGPT 网页版输出；
- `00首页信息.json`：供通用网站模板直接消费；
- `00首页模块.json`：首页 Explore 模块；
- `facts.json`：规范化事实；
- `evidence.json`：字段级来源；
- `validation-report.json`：错误、警告和需要人工确认的字段；
- `raw/`：保存上游原始结果，便于重跑和排查；
- `assets/`：图片候选和 favicon。

## 5. 规范化事实结构

`facts.json` 是整个流程的事实中心。后续模型不得绕过它重新解释已确认的 Roblox 字段。

```json
{
  "identity": {
    "query": "Anime Expeditions",
    "canonicalName": "Anime Expeditions",
    "currentRobloxName": "Anime Expeditions [TIME CHAMBER]",
    "slug": "anime-expeditions",
    "platform": "Roblox",
    "placeId": "84515722934860",
    "universeId": "7613921865",
    "canonicalUrl": "https://www.roblox.com/games/84515722934860/Anime-Expeditions",
    "matchConfidence": 0.99
  },
  "developer": {
    "name": "Expeditions Entertainment",
    "type": "Group",
    "id": "35929511",
    "url": "https://www.roblox.com/communities/35929511/Expeditions-Entertainment"
  },
  "game": {
    "officialDescription": "",
    "genre": "Strategy / Tower Defense",
    "maxPlayers": 24,
    "createdAt": "2025-04-28T17:56:58.9Z",
    "updatedAt": "2026-07-16T07:33:27Z"
  },
  "dynamicStats": {
    "retrievedAt": "2026-07-16T08:00:00Z",
    "playing": 109642,
    "visits": 13335318,
    "favorites": 20938,
    "approvalPercent": null
  },
  "officialLinks": {
    "website": null,
    "roblox": "",
    "robloxGroup": "",
    "discord": null,
    "reddit": null,
    "youtube": null,
    "trailer": null,
    "x": null,
    "tiktok": null
  },
  "codes": [],
  "media": {
    "icon": null,
    "thumbnails": [],
    "heroImages": []
  }
}
```

### 5.1 动态字段

以下字段必须带 `retrievedAt`，不能长期写死：

- playing；
- visits；
- favorites；
- approvalPercent；
- current active codes；
- current Roblox title；
- latest update date。

### 5.2 兑换码结构

事实层不强制两条：

```json
{
  "code": "RELEASE",
  "reward": "30 Trait Crystals and 2,500 Gems",
  "status": "claimed-active",
  "officiallyVerified": false,
  "retrievedAt": "2026-07-16T08:00:00Z",
  "sourceIds": ["src_21", "src_24"]
}
```

`status` 可选：

- `verified-active`：官方来源明确确认；
- `claimed-active`：多个可靠第三方声称有效，但官方页面无法验证；
- `expired`：有可靠来源确认过期；
- `unknown`：状态不明。

首页默认只展示 `verified-active`。若业务决定展示 `claimed-active`，必须显示“Unverified”标记。

## 6. 证据结构

`evidence.json` 保存所有来源：

```json
{
  "sources": [
    {
      "id": "src_1",
      "url": "https://www.roblox.com/games/...",
      "title": "Anime Expeditions | Play on Roblox",
      "sourceType": "official-platform",
      "publisher": "Roblox",
      "retrievedAt": "2026-07-16T08:00:00Z",
      "httpStatus": 200,
      "accessible": true
    }
  ],
  "claims": [
    {
      "field": "developer.name",
      "value": "Expeditions Entertainment",
      "sourceIds": ["src_1"],
      "confidence": 1.0,
      "classification": "fact"
    }
  ]
}
```

### 6.1 来源等级

|等级|来源|默认可信度用途|
|---|---|---|
|A|Roblox 官方 API、官方游戏页、开发组官方页面|可以直接形成事实|
|B|由官方页面直接链接的 Discord、YouTube、X、官网|可以形成官方链接事实|
|C|官方账号内容、官方视频描述、官方公告|可以形成对应公告事实|
|D|权威媒体、可靠创作者、社区 Wiki|只能用于补充或交叉验证|
|E|普通聚合站、无署名页面、搜索摘要|只能作为候选，不直接上线|

竞对 Wiki、Fandom 和聚合 Wiki 不进入前台 `references`；内部可以记录它们作为发现线索，但不得单独证明重要事实。

## 7. 首页配置结构

`00首页信息.json` 尽量兼容原始 Prompt，同时补充真正需要的 URL。

```json
{
  "home": {
    "meta": {
      "title": "",
      "description": ""
    },
    "hero": {
      "eyebrow": "",
      "title": "",
      "description": "",
      "stats": [],
      "primaryCta": "",
      "secondaryCta": "",
      "tertiaryCta": "",
      "videoLabel": "Official media"
    },
    "start": {
      "eyebrow": "Start Here",
      "title": "",
      "cards": []
    },
    "aboutGame": {
      "title": "",
      "paragraphs": [],
      "stats": [],
      "cta": "Explore All Guides"
    },
    "finalCta": {
      "title": "",
      "description": "",
      "primary": "",
      "secondary": ""
    }
  },
  "footer": {},
  "shared": {},
  "sidebarCodes": [],
  "metadata": {},
  "links": {},
  "theme": {},
  "languages": []
}
```

### 7.1 字段规则

#### SEO

- `home.meta.title`：1–60 个字符；
- `metadata.title`：1–60 个字符；
- 两个 description 均为 140–160 个字符；
- `metadata.keywords`：1–100 个字符；
- 长度按 Unicode code point 计算，不按 token 计算；
- 英文 description 不允许为了长度堆砌关键词。

#### Hero stats

原文同时出现“4 组数据”和 5 个示例，统一为：

- 恰好 5 个纯字符串；
- 最多 2 个动态统计；
- 优先选择玩家直觉强、来源可靠的数据；
- 不展示 0；
- 不把“Official Discord hub”一类链接标签当作统计；
- 每个动态数字在内部关联 `retrievedAt`。

推荐顺序：

```text
状态/发布日期 → 最近更新 → 当前玩家/访问量 → 核心规模 → 服务器/玩法特征
```

#### Start cards

- 恰好 4 张；
- 第 1 张固定为 Beginner Guide；
- 其余三张必须对应真实玩法；
- 卡片之间不能只是同义改写；
- title 和 description 使用英文。

#### About stats

- 5–7 项；
- Developer、Platform、Genre 必填；
- 其余只选有来源的事实；
- 不知道等级上限时不得生成；
- 动态统计使用格式化值，如 `13.3M+`，原始数值保存在 facts。

#### Footer links

原 Prompt 只有按钮文字，无法真正跳转，因此新增统一 `links`：

```json
{
  "playGame": "https://...",
  "officialDiscord": null,
  "officialYoutube": null,
  "officialTrailer": null,
  "officialX": null,
  "reddit": null
}
```

#### Sidebar codes

事实层允许 0–N 条。为兼容现有模板，渲染层输出恰好 2 条：

- 有两条官方确认码：输出两条；
- 只有一条：第二条使用占位；
- 没有官方确认码：两条都使用占位；
- 第三方声称有效的码默认不冒充 `Active`。

## 8. 主题色规则

主题色属于 Inference，不属于游戏事实。

输出：

```json
{
  "defaultMode": "dark",
  "light": {
    "navTheme": "202 88% 48%",
    "navThemeLight": "190 90% 57%"
  },
  "dark": {
    "navTheme": "198 92% 58%",
    "navThemeLight": "187 95% 68%"
  },
  "reason": "",
  "confidence": 0.82
}
```

要求：

- 优先从 Roblox 官方图标和缩略图提取主色候选；
- 模型根据视觉和类型选择最终 HSL；
- 亮色与暗色可以不同，禁止机械复制；
- 必须通过对比度检查后才能进入最终配置；
- 默认模式只能是 `light` 或 `dark`。

## 9. 多语言规则

输出 1–4 门语言：

- English 必须存在并排第 1；
- 中文不进入本项目输出；
- 不能为了满足 4 门而硬凑；
- 品牌游戏名默认不翻译；
- 每门语言必须记录 evidence 或 inference；
- 没有游戏特定证据时，只能标记为低置信度市场推断。

```json
{
  "rank": 2,
  "code": "pt-BR",
  "language": "Português do Brasil",
  "localizedSiteName": "Anime Expeditions Wiki — Códigos e Tier List",
  "gameName": "Anime Expeditions",
  "basis": "inference",
  "sourceIds": [],
  "confidence": 0.55
}
```

第一版可以接受模型推断；正式上线后应以 Google Search Console 实际流量替换推断排名。

## 10. Hero 图片规则

原 Prompt 要求“5 个直接下载链接”，但模型容易返回网页 URL、过期 URL 或假链接。

统一规则：

- 最多 5 张，不强制恰好 5 张；
- 优先 Roblox 官方缩略图 CDN；
- 其次官方 YouTube 视频缩略图；
- 每个 URL 必须实际请求验证；
- 检查 HTTP 200、Content-Type 为图片、最小尺寸和宽高比；
- 不将搜索结果页面 URL 当图片 URL；
- 不足时明确输出缺失，不由文本模型虚构。

```json
{
  "url": "https://tr.rbxcdn.com/...",
  "originUrl": "https://www.roblox.com/games/...",
  "sourceType": "official-platform",
  "width": 768,
  "height": 432,
  "contentType": "image/webp",
  "verifiedAt": "2026-07-16T08:00:00Z"
}
```

## 11. 首页模块规则

原文要求恰好 8 个模块，这会在小型或新游戏上造成凑数。统一为：

- 目标 8 个；
- 允许 4–8 个；
- 模块必须存在真实用户需求和可用资料；
- 不足 8 个时在验证报告说明，不生成无意义模块；
- 每个模块必须有 2–4 条 highlights；
- `displayType` 仍限制为原有四种；
- references 至少 1 个，且前台不得包含竞对 Wiki/Fandom/聚合 Wiki；
- Tier List 必须标记观点来源和更新时间，不能伪装成官方排名。

允许类型：

```text
code-cards
step-by-step
tier-grid
card-list
```

模块选择优先级：

```text
真实搜索需求
→ 游戏核心机制
→ 资料充足度
→ 首页展示价值
→ 是否能形成对应内页
```

## 12. API 任务拆分

### Task 0：Roblox 游戏身份发现

输入：

```text
gameName
```

数据源：

- Jina Reader + Roblox Discover；
- Roblox 搜索页结果；
- 必要时 ToAPIs Responses 联网模型做同名消歧，最终仍由 Roblox API 确认。

输出：

```text
candidate games
selected placeId
selected universeId
match confidence
```

该任务不生成网站文案。

### Task 1：Roblox 官方事实采集

输入：

```text
placeId + universeId
```

数据源：

- Roblox 公开游戏详情；
- Favorites；
- Thumbnails；
- Groups/Users；
- Localization。

输出：`facts.json` 的 Roblox 部分。

该任务不调用 LLM。

### Task 2：外部官方资源研究

输入：

- 用户游戏词；
- 已确认 Roblox 名称、URL、开发组和描述；
- 明确需要寻找的字段。

主 API：

```text
ToAPIs gpt-5.3-codex-official + Responses web_search_preview
```

研究字段：

- 独立官网；
- Discord；
- Reddit；
- YouTube channel；
- Trailer；
- X/TikTok；
- 发布状态；
- 兑换码候选；
- 玩法事实候选；
- 语言信号。

要求模型只返回“候选事实 + 来源 + 置信度”，不在该任务写 Hero、SEO 或 CTA。

### Task 3：首页配置生成

输入：

- `facts.json`；
- 经过验证的 claims；
- 首页 JSON Schema。

模型不联网，或默认关闭联网工具。它只负责：

- Hero 文案；
- Start cards；
- AboutGame；
- Final CTA；
- Footer 和 Shared；
- SEO 文案；
- 主题色判断；
- 多语言配置。

输出：严格 JSON，不输出解释。

### Task 4：首页模块研究与生成

输入：

- 游戏事实；
- 已确认玩法；
- 外部研究结果；
- 模块 Schema。

模型可以联网，但先做模块候选，再为选中的模块补 highlights。为控制成本，最多两轮：

1. 规划 4–8 个模块；
2. 批量补充所有模块数据。

### Task 5：媒体与 favicon

分为：

1. Roblox/YouTube 图片候选发现；
2. 图片 URL 验证；
3. favicon Prompt 生成；
4. 图片模型生成 512×512 PNG；
5. 本地转换各尺寸 favicon。

该任务与首页文本失败相互独立。

### Task 6：验证与报告

不调用联网模型，完成：

- Schema；
- 字符长度；
- URL；
- 图片；
- 数组数量；
- 重复模块；
- 来源等级；
- 动态字段时间；
- 事实与文案混用检查。

## 13. ToAPIs Responses 使用策略

### 13.1 默认职责

默认 `gpt-5.3-codex-official` 主要用于：

- Task 2 外部资源研究；
- Task 3 高质量文案；
- Task 4 模块规划和数据整理。

### 13.2 搜索控制

联网模型可能自主执行多次搜索。第一版必须限制：

- Task 2 只搜索明确字段；
- Prompt 明确要求先使用官方来源；
- 将 Roblox 事实放入上下文，禁止重新搜索已确认字段；
- 默认使用 low reasoning；
- Prompt 严格限定待查字段，已确认 Roblox 字段不得重复搜索；
- 每个游戏设置费用上限；
- 达到预算后返回 partial，而不是继续搜索。

ToAPIs 当前文档未提供 `web_search_preview` 的搜索次数或结果数硬上限；`usage` 和实际 `web_search_call` 只能在响应完成后审计。

### 13.3 暂定预算

基于本轮实测，先设设计目标：

|任务|目标成本|警戒线|处理|
|---|---:|---:|---|
|身份消歧|≤ $0.10|$0.20|超过则停止并进入候选审核|
|外部资源研究|≤ $0.25|$0.50|超过则返回 partial|
|首页生成|≤ $0.10|$0.20|不联网，超限截断并重试|
|模块研究|≤ $0.30|$0.60|减少模块或降低搜索深度|
|单游戏合计|≤ $0.75|$1.25|超过必须停止自动扩展|

这些不是最终价格承诺，需在拆分流程样本测试后调整。

## 14. 超时、重试与降级

### 14.1 超时

|任务|软超时|硬超时|
|---|---:|---:|
|Roblox/Jina|20 秒|45 秒|
|GPT 外部研究|120 秒|300 秒|
|GPT 首页生成|90 秒|180 秒|
|模块研究|180 秒|360 秒|

软超时只记录慢请求；硬超时终止当前任务。

### 14.2 重试

- 网络 429/5xx：指数退避后最多重试 2 次；
- 结构错误：不重新搜索，只把原响应交给修复模型或本地修复；
- 空响应/`null`：缩短任务后重试 1 次；
- 事实冲突：不自动重试相同 Prompt，切换到冲突验证任务；
- 认证错误：立即停止，不重试。

### 14.3 降级顺序

```text
ToAPIs Responses + web_search_preview
→ Perplexity fast-search 补候选来源
→ 保留缺失字段并输出警告
```

降级不会覆盖已经由 A/B 级来源确认的字段。

## 17. 现有 Prompt 的修订决定

### 保留

- 首页原有字段；
- 英文网站文案；
- 4 张 Start cards；
- SEO 字符限制；
- 主题色 HSL；
- 最多 4 门语言；
- 原有四种模块展示类型；
- favicon 512×512 Prompt。

### 修改

- Hero stats 统一为 5 条；
- 首页模块从强制 8 个改为目标 8 个、允许 4–8 个；
- Hero 图片从强制 5 个改为最多 5 个已验证图片；
- Codes 事实层不强制两条，渲染层再兼容两条；
- 多语言不强制凑满 4 门；
- 官网不存在时明确回退 Roblox 游戏页；
- 所有动态字段增加采集时间；
- 所有重要事实进入证据层；
- 搜索与文案生成不再放在同一个超长 Prompt。

### 删除或禁止

- “没有 Trailer 就随便选一个爆款视频”；
- 无来源的 Tier List；
- 仅凭通用 Roblox 市场常识声称具体语言热度；
- 不经请求验证的下载链接；
- 将搜索摘要直接视为官方事实；
- 模型用自然语言声称“自查通过”而没有程序验证。
